**当前只交付界面原型，真实多人、账号、统计和防篡改由后续Codex实现。** 内部版本0.7.2，下载包仍为 `FlightParty-v0.7.zip`。本文件替代旧的匹配设置、手动成绩上传/认领及胜利/胜率榜方案。

保留v0.6.2道路标定、同一飞机/阴影/点击投影、低路缘、3D骰子、固定选机区和原本地引擎。`engine.js` 未改，新结束条件仍待实现。示例数据、房间和倒计时必须邻近标注“本地预览 / Preview”；不能声称已经匹配真人、真正登录或保存成绩。实际检查见 `QA.md`，旧测试不代表新服务已实现。

本原型的30秒倒计时可运行，到期只展示机器人补位后的开局预览；点击“试玩一局本地电脑对局”可进入原有本地玩法。这是评审入口，正式联机版须在满员或30秒到期后自动开局，不要求用户再点一次开始。

## 简化后的页面与流程

首页主要入口只保留 **快速匹配、创建房间**；房码加入是次级入口，单人练习继续保留。线上原型默认经典四席，不再先问人数、模式或是否接受机器人；这是本版简化的实现默认值，不是将全部玩法永久锁定为四人。原本地练习仍可配置2–4个阵营，经典与派对规则继续隔离。

| 入口 | 用户操作与后续真实行为 | UI重点 |
|---|---|---|
| 快速匹配 | 点击即加入有空位的公共匹配房；没有合适房间就自动创建 | 直接显示席位与剩余等待时间，不再弹出设置表单 |
| 创建房间 | 点击进入好友等待房，可分享链接/房码邀请朋友 | 成员列表、邀请、准备起飞；等待朋友时没有30秒倒计时 |
| 准备起飞 | 当前在房的真人各自准备，全部准备后整房进入公共匹配，保留朋友的原席位 | 填充其他真人；满员立即开始，最多等待30秒 |
| 30秒到期 | 自动用机器人补满空席并开始；即使只剩一名真人也可与机器人玩 | 明确区分真人和BOT，不另弹补位确认 |
| 结算 | 登录账号自动保存服务器确认的成绩；匿名不保存累计统计 | 无手动上传/认领按钮；未接后端时仅展示状态预览 |

### 匹配与准备的确定性规则

- 服务器只将快速匹配玩家分配到已进入公共匹配、尚未开始且有空位的兼容房。好友等待阶段保持邀请可见，不接收陌生匹配玩家；全员准备后才开放剩余席位。
- 一名创建者也可点击“准备起飞”进入匹配。已在好友房的成员每人独立准备；新朋友加入时为未准备，已有成员的准备状态不必清空。成员离开后重新判断当前真人是否全部准备；全体离开则清理等待房。
- 快速匹配入座等同于同意开始，不需再点准备。进入公共匹配后不提供取消准备；可在开局前离开。朋友在同一房间进入匹配，不拆散、不把已占席位移交陌生人。
- 30秒从房间第一次进入公共匹配的服务器时间起算。后来加入者沿用该房剩余时间；加入、离开、刷新或重连都不重置截止时间。全真人满员可提前开始；到期由机器人补空席，已有真人不会被替换。
- 分配席位、到期补位与开始必须原子处理：抢最后一席最多一人成功；到期与新加入并发只认一个结果。开始只执行一次，开始后拒绝新入座；原参与者重连例外。旁观暂不包含。
- 等待与取消不扣局数，正式成功开局才扣一次。取消和开局并发时以服务器结果为准；已开始后离开按机器人托管处理。若真人全离开，不启动全机器人空房。
- 经典和派对不能混池；本轮线上默认经典，若后续开放派对，保持独立入口/队列，不重新给快速匹配增加繁琐设置。

## 结束、积分和排行榜

- 每阵营两架飞机。前两名各自两架都到达终点后，立即结束全局；两人局仍需双方完成。
- 其余玩家先按已完成飞机数、再按飞机进度排定名次。名次分为 **第一+2、第二+1、第三-1、第四-1**；只处理实际参赛席位。
- 原生机器人占名次但没有账号统计、不入榜。接管真人的机器人仍属于原真人席位，成绩归原账号。
- 首页只提供 **积分榜、对局数榜**，各Top10总榜。积分榜按累计积分，对局数榜按正式完成并结算的局数；等待、取消、重连不算完成一局。已绑定登录账号的参赛者每次正式结算都只增加1局，输赢都计。移除胜利榜和胜率显示，玩家卡片改为积分与对局数。
- 匿名不建立累计积分或对局数，不入榜。榜单仅来自服务端正式结算的数据，不能使用浏览器本地计数。
- 未完成者精确进度比较建议：完成架数优先，再比较两架总前进步数；仍同分则比较最远未完成飞机，最后使用固定席位顺序。精确算法及榜单同分排序属于后续实现细节，需确定并测试。
- 起飞、移动、撞机、安全格、私人航道及终点规则不随本次改动改变，详见 `RULES.md`。

## 账号与自动记录

**匿名和登录用户都能玩；登录后由服务器自动记录结果，不要求用户点击上传。** 登录账号的胜局、负局和负积分都必须保存，不能只挑选好成绩上报。取消旧的匿名结算后手动登录认领方案和相关claim接口；匿名历史不追补。

实现默认：正式开局时，服务器固定每个参与席位的accountId；已绑定账号的本局一定记入该账号，包括负分。退出登录、会话过期、断线或机器人托管不能清除该绑定，也不能逃避结算。结算依据比赛参与记录，不依赖当时浏览器是否登录。为简化本版，匿名在对局中登录只影响后续新局，本局不追补；等待房阶段登录可在正式开局时绑定。重新认证须证明原席位所有权，不能让客户端替换结果接收账号。

- 邮箱+密码注册/登录，不需要邮箱验证码，不把邮箱标为已验证；保留Google、GitHub入口，真实授权留待后续接入。
- 后端保存带盐的安全密码哈希，使用受保护的登录会话；第三方身份使用提供方稳定用户ID，不能仅凭相同未验证邮箱自动合并账号。UI预览不保存或发送密码，也不能提示真实认证成功。
- 普通用户每天20局、会员不限保留。匿名同20局和UTC每日重置仍为实现建议，未另获产品确认；不能恢复“匿名仅玩一局”。
- 正式开局按matchId和参与身份只扣一次；多人资格与额度检查、扣次、开始需要一致处理，不能失败后部分扣次。登录不能清零同日匿名已用次数，重连不增加用量。
- 会员校验来自后端；支付接入和部署不是当前UI任务。

## 防篡改：后续必须实现

| 对象 | 服务端要求 |
|---|---|
| 骰子和玩法 | 服务器生成随机点数，验证当前回合、阶段、合法飞机和路线，决定撞机、终点及名次；客户端仅发送掷骰/选飞机意图 |
| 房间和身份 | 每条请求验证会话、房间成员和席位所有权；不能操作他人飞机、伪造准备、冒充房主或变更账号绑定 |
| 时间与机器人 | 匹配30秒、回合截止和机器人决策均由服务端执行；修改本机时间、暂停页面或关闭标签不能改变结果 |
| 重放与乱序 | 命令携带唯一commandId及匹配/回合标识，服务端按状态处理并去重；事件带递增seq，重连先取权威快照，旧请求不能重复移动 |
| 统计与榜单 | 不接受客户端自报骰子、最终名次、积分、对局数或会员状态；服务器从正式结果计算points与games |
| 重复结算 | matchId结算、matchId+seatId成绩和扣次有唯一约束；事务一次写入结果及账号增量，重试返回既有结果，不重复加分/加局数 |
| 连接与滥用 | 正式部署使用HTTPS/WSS、会话保护与必要的来源校验；登录、建房、匹配和表情有速率限制，记录异常请求供排查 |

“防篡改”指修改浏览器代码、请求参数或本地存储不能改变其他玩家的权威对局和账号统计；不承诺客户端无法被修改或绝对无作弊。代码混淆、前端隐藏字段或客户端签名不能替代上述服务端校验。断线、重启和重试也必须保持结算、扣次和统计幂等。

## 断线与表情

- 断线或主动下线由服务器机器人接管原席位；不删除玩家、不新建参与者、不重置飞机。其他玩家看到托管状态，重连恢复原房间最新状态并在安全决策点交还控制。
- 机器人已提交的动作不能回滚，同一席位不能同时接受人和机器人的操作。已结束后重连只显示既有结果；登录账号的托管结果仍自动保存。
- 表情事件由服务端验证成员并广播给全房间，界面显示发送者头像、昵称和表情。当前 `reaction-preview.js/.css` 仍是本地演示，不能称为共享成功。

## 后续开发与验收顺序

1. 先验收本版简化UI，保留 `design/gameplay-reference.png` 及历次反馈图；只为真实接入的功能移除预览标识。
2. 实现新结束条件与积分/对局数规则，覆盖2/3/4人名次；测试后才更新旧engine哈希保护。
3. 实现账号、席位身份、额度和一次性结算事务；去掉手动上传/认领路径，登录完整成绩自动记录、匿名无累计统计。
4. 实现快配入空房/自动建房、好友等待与全员准备、公共匹配30秒补位、满员提前开始、断线机器人和重连；至少两个独立客户端实测。
5. 验证恶意客户端改点数/步数/账号/分数被拒绝，重复命令与重复结算不增加结果，抢位/到期/取消并发不会双重开局，改本机时钟不影响服务端倒计时。
6. 接真实排行榜和全房间表情，补真实移动端、GPU、错误与空态验收。当前本地原型测试不能代替这些验证。

后续技术栈可沿用Node服务与事务数据库，也可选择团队熟悉的后端；本轮不迁移buildless启动。房间快照至少包含matchId、seq、phase、席位身份/控制者、棋子、骰子、排名及截止时间。接口接收动作意图，不公开任意成绩写入端点。

尚需后续定稿的细节：线上默认四席是否开放其他人数、精确同分比较、练习/派对局是否计分和计额度、匿名日额度/重置时区。对局中登录默认仅后续新局生效，若以后调整，仍须禁止按结果选择保存和退出登录逃避负分。以上不阻断UI交付，不改变已明确的30秒自动补位和登录自动记录。
# 最新产品变更：不限对局次数

进一步更新：每天首局已完成的登录对局自动使用 1 次免费成绩记录资格，正负分均记录；后续游戏仍可无限玩，会员可无限记录。会员使用 Creem 支付，月付 9 USD、年付 59 USD。首局以服务端结算事务获取资格为准，日界暂用 UTC。下面原“所有登录对局均累计”的描述由本条覆盖。

用户最新要求覆盖本文历史额度条款：匿名和登录玩家均不限对局次数，不计算、不扣减每日额度；会员不再决定可玩次数。仅开局时登录的账号自动累计服务器确认的积分与完成局数，匿名和原生机器人不累计；保留开局账号归属冻结，退出登录不能逃避负分，匿名结算不支持事后认领。不提供客户端自行提交分数的接口。

## 2026-11-01 最新用户覆盖：游客局中途登录
游客当前对局尚未结束时登录/注册，可以将该席位首次绑定到账号，当前局按每日首局免费、会员不限记录规则结算。不同窗口的不同对局可归属同账号；同局同账号最多一个记分席位。已绑定的归属不可通过退出/切换账号移除或转移；已完成游客局不补领。此条覆盖历史仅开局登录计分和中途登录仅用于后续局条款。

## 2026-11-01 匹配来源与再来一局
快速匹配入口不显示邀请链接/房码，再来一局重新匹配。好友房保留邀请入口；结束并结算后，再来一局原子创建唯一新房，保留房主和受邀朋友，去掉电脑及公开匹配补位玩家，回到等待好友准备阶段，无倒计时；准备后沿用既有匹配/补电脑规则。每个成员视图分别记录来源，快速匹配补位者仍按QUICK处理。已另进其他房间的朋友不会被抢回，新建失败提示重试。发布前没有来源数据的旧房间按QUICK兼容，不臆测好友关系；新房完整记录来源。

## 2026-11-01 等待房退出与连接租约
等待好友和公开匹配均提供明确退出按钮，主动退出立即移除当前主体席位并释放占用。浏览器关闭不依赖unload/beacon：服务端WebSocket Ping/Pong维护每连接租约；同主体其他窗口仍在线时保留席位，全部断开后15秒宽限，尚未开局的席位自动移除。短暂刷新/重连在宽限内保留；已开局继续原席位自动代玩和原账号结算，不通过断线清除负分。若30秒匹配期限先到而已开局，则遵守已开局规则，不延长原匹配倒计时。清理通过房间版本及Redis内在线租约的原子检查，避免扫描后重连仍被踢。好友续局预留席位同样需要连接，不永久保留离线成员。

2026-11-01 用户覆盖：首页改为月、周、日积分榜，UTC自然周期，周一为周起点，按已记录结果的结算时间统计。移除首页对局数排行入口。展示补充数据逐行标记示例，不进入真实账号或成绩账本。
