# 会员与支付契约

更新：2026-11-23。本文覆盖 [2026-10-31 旧规则](archive/MEMBERSHIP-CONTRACT-20261031.md)；运维配置见 [Creem 支付手册](CREEM-PAYMENTS.md)。

## 免费游玩与成绩

所有玩家游玩不限次数。所有合资格登录对局由服务端权威结算并自动记录积分与完成局数，包括负分；匿名对局不累计。资格和托管结束席位的处理以当前服务端结算规则为准。不存在“每日首局免费记录、会员无限记录”的差异，会员不增加积分、骰子概率或获胜机会。

## 套餐与权益

- Creem 月度 USD 9、年度 USD 59，按选定周期自动续订，直到取消续订；税费以结账页为准。
- 会员提供徽章、合资格头像框、飞机、尾迹及胜利效果等外观，年度专属外观取决于明确的年度资格，不根据剩余天数推断。
- 有效正式订阅由已验证的服务端 `ACTIVE`、`test_mode=false` 和未过期状态判定。到期、撤销等状态由可信事件更新。
- `TEST_ACTIVE` 是测试订阅，不授予正式付费会员。赠送会员单独记录，不生成付款凭证，也不能证明 Creem 支付成功。

## 开通、有效期与重复购买

账号面板展示服务端返回的会员状态、套餐、有效期与自动续订状态。`paymentConfigured=true` 只表示当前账号可使用结账，并不表示已经付款。

服务端拒绝当前模式下尚在有效期内的重复订阅，前端同步禁用对应购买入口；已取消自动续订但仍在有效期内，也不应重复购买。正式与测试订阅按模式隔离，赠送会员与付费订阅分别处理。当前没有已验证的前端套餐升级、降级或人工叠加时长流程，不能把重复购买当作升级。

创建 Checkout 需要已认证会话、有效 CSRF、服务端方案名 `MONTHLY` / `ANNUAL` 以及 UUID `requestId`。同一订单重试复用原 UUID；未知结果先对账，不反复创建。客户端不能自报会员或分数。

## 支付确认与订阅生命周期

- 回调对原始请求体按 `creem-signature` 验签，事件去重并校验模式、产品、USD 金额、周期、交易状态和服务端账号绑定。
- 通过验证的 `subscription.paid` 才授予或更新对应模式的权益。Checkout 返回、前端标志、截图及单独的 `checkout.completed` 不授予会员。
- 取消自动续订调用当前模式的 Creem API，并校验订阅归属；已付周期通常保留，不自动退款。
- 退款、争议、暂停、取消、到期与乱序事件依据服务端对应交易和事件处理，不接受客户端单方面修改。

## 配置与当前验证状态

正式与测试各保留一套 `CREEM_PROD_*` / `CREEM_TEST_*`；`CREEM_LIVE` 同时控制订单、验签、权益同步和取消续订，不能混用两种环境。切换需重建 backend，完整命令与回滚见支付手册。

截至 2026-11-23 最近部署记录，线上为正式支付。商户、正式产品、签名回调连通和正式待付款收银台已验证；未据此宣称首次正式扣款、真实付费会员到账、正式续订或取消扣费已完整验收。历史沙盒付款成功不等于正式付款成功。
