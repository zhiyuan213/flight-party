## 当前已实现的基础规则

- 2–4个阵营，每方真人、电脑或关闭；至少一方真人。启用阵营各自竞争，不是2v2。
- 蓝、橙、绿、红，每方两架飞机；当前真人在同一设备轮流操作。
- 每回合掷一次1–6点骰子，选择一架未到终点的飞机；无掷六点奖励回合。
- 不设特定起飞点数，任何点数可以出发。
- 落在敌机所在公共格触发撞击，敌机回基地。
- 达到或超过终点所需步数即可到达，无需刚好点数。
- 操作15秒，超时由本地电脑选择；动画期间不扣时。这不等于联网断线接管已经实现。

## 当前原型参数与旧结束条件

- 公共路线52格，坐标在 `engine.js` 的TRACK，每方起点相距13格。
- 各方5格私人航道，走完后到中心终点；进度0–51为公共格，52–56为私人格，57为完成。
- 基地进度为-1，掷1前进到本方起点0；掷N起飞前进到N-1。
- 四个起点是安全格，不发生撞击。私人航道没有敌方碰撞。
- 同方飞机可同格，不形成阻挡或加成；当前可能视觉重叠，后续需增加叠放展示。
- 同格有多架敌机时一并撞回，每架计1次撞击。
- **旧引擎仍如此运行**：第一名先到两架即记录名次，后续玩家继续，剩最后一方时自动给最后名次并结算。此条将在后续功能开发中被新结束条件替换。
- 关闭阵营仍显示其机场，但没有棋子、不参与回合和投票。

## 后续新规则（本轮只做UI）

- 前两名各自两架飞机都到终点后立即结束；两人局也需双方完成。其余按完成飞机数量、再按进度排定；精确同分比较见V07-CONTRACT建议，后续确定并测试。
- 名次分+2、+1、0、-1。原生电脑参与名次但无账号统计；接管真人的机器人成绩仍属于原身份。
- 登录账号自动记录服务器确认的完整结果，包括负分；账号在正式开局时固定，退出登录不免除本局结算。匿名局中登录默认从后续新局记录；匿名不保存累计积分或局数。没有手动上传/认领流程，不接受客户端自报分数，不追补匿名历史。
- 排行仅积分榜、已完成对局数榜各Top10，移除胜利榜和胜率显示。完成局指正式结算，输赢均只增加1局；取消、等待、重连不算一局。
- 快速匹配直接进入公共空位房，无房自动创建；从房间开始公共匹配起最多30秒，满员提前开始，到期机器人自动补齐。后来加入、离开、重连不刷新时限。
- 创建房间等待邀请朋友，当前真人各自点准备起飞，全员准备后原房加入公共匹配补其他真人；朋友不拆散。邀请等待时不倒计时，一名房主也可准备后开始匹配。
- 线上简化UI默认经典四席，去掉匹配配置表单；这是实现默认，本地2–4阵营选择仍保留。派对与经典不混池，不改基础飞行规则。
- 匿名/登录均可玩；普通每日20局、会员无限；匿名同20局和UTC重置为建议。成功开局扣一次，登录承接同日匿名用量，重连不扣新次数。
- 邮箱密码注册登录无邮箱验证码，保留Google/GitHub入口；不能凭未验证同名邮箱自动合并账号。当前无真认证。
- 断线或主动下线由机器人继续同一席位，重连恢复控制；同局不重复扣次、不重复结算。表情后续向全房间广播，当前仅本地预览。
- 服务端负责骰子、合法动作、回合/匹配时间、名次与统计；验证席位所有权、拒绝客户端修改数据，通过唯一命令与结算事务防重放。修改浏览器不能改变权威对局；当前UI原型尚未具备此安全边界。

## 当前实验性派对模式

- 大厅明确选择Party才启用。经典模式无投票、无道具，不与派对规则混用。
- 完成一轮后逐个未完成阵营投票，每方1票，电脑自动投票。最多4票。
- 二选一：Tailwind全部移动+1（包括基地起飞）；Peaceful skies本轮所有公共格不可撞击。
- 平票随机二选一。事件仅持续下一轮，不叠加；新一轮投票替换。
- 无付费能力，不改变基础投骰概率。未来练习局/派对局是否计入统计与额度仍待确认。

## 当前状态机与后续权威边界

`roll → choose → animating → 下一回合 roll / 下一轮 vote / over`

- 状态机拒绝重复掷骰和重复移动。
- 规则先结算，界面播放同一结果；动画过程中禁用操作。
- 后续联网开发必须由服务器产生规则结果，客户端只渲染，不信任客户端骰子或名次；断线恢复与机器人接管不能重放已经提交的动作。

## 2026-11-05 台球：15 球分组玩法（用户确认）

本节取代此前 1–7 号共用目标的休闲台球规则。首次有效落袋的全色（1–7）或花色（9–15）决定击球者组别，对手分配另一组。有效指先碰合法目标且白球未落袋；同杆进多球时按物理模拟落袋顺序确定。未分组时 8 号不是合法首碰目标。

打进本组球且未犯规继续击球；未碰目标、误先碰对方球或白球落袋换手。白球落袋自动复位。顶部显示本组仍在台面的目标球，全部清空后显示 8 号。必须在开杆时已清空本组，合法打进 8 号才获胜；提前进 8 号或同杆白球落袋判负。200 杆上限保留，按本组已清空数量比较。该版本仍为休闲分组玩法，未实现指定袋、自由球摆放或完整赛事开球犯规规则。


2026-11-05 台球用户力度调整：相同1–100力度指令对应的初速度翻倍（power×0.40/原8ms速度单位），旋转冲量同比；使用2ms子步保持高速碰撞稳定，每秒阻尼和回放采样周期不变。全色/花色、犯规、8号球判胜规则不变。

2026-11-05 台球物理修正（历史记录；当前参数见 §2026-11-10）：后续按用户要求减20%，当前初速度为power×0.32，旋转冲量同比，2ms子步和16ms回放保留。落袋依据球心进入实际可见洞内轮廓；经过袋前或停在袋前不会吸入。直库、斜口和圆角袋颚按相同胶垫接触模型反弹。JS与Java同步实现；全色/花色、犯规及8号判胜规则不变。袋内回弹、桌下输送与对手出杆均为结果表现，不重新决定比分或击球指令。

## 2026-11-06 台球犯规与额外一杆

白球落袋或未先碰合法目标均判犯规，换手并给对方一次额外出杆机会。合法打进本组球可继续且保留机会。第一次合法击球未进本组球后，仍由同一人出杆，画面标示「本杆为额外罚杆」。额外一杆打出后即消耗，合法进本组球仍按普通规则连杆。犯规弹出提示，写明犯规方和原因。同杆同时触发两项犯规时只给一次额外机会。提前进黑八、黑八杆犯规和 200 杆结算仍直接结束。新状态尾部增加一个罚杆字段，既有 52 格状态以无罚杆读取。

## 2026-11-10 台球旋转物理升级（当前版本）

以 `docs/POOL-SPIN-PHYSICS-UPGRADE.md` 为设计依据，实施 bounded rigid-body 近似，替换 2026-11-05 起使用的一次性旋转冲量模型。**当前初速度为 `power×0.48`**（原 8ms 速度单位）；2ms 子步、16ms 回放、球心入洞判定，以及整数指令 `spot*363600 + power*3600 + angle`（spot 0–8）均未变更。协议格式保持兼容，但物理结果不同，升级后须结束旧局重新开局。

- 每球新增 `wz`（垂直轴侧旋）与 `top`（高/低杆）两个衰减状态量，只存在于模拟内部，**不进入 53 格状态，也不进入 16ms 回放帧**。
- 侧旋通过台呢接触斑摩擦产生弧线，横向加速度归一化后只改方向、不增速；不引入马格努斯项，不模拟跳球。
- 高/低杆调制滚动阻尼，并在**每次**真实碰撞按剩余旋转预算施加跟进/回缩冲量；取消 `contactSpin` 一次性锁存与 `spinLife`。
- 球-球恢复系数 `e_ball=0.95`（原为完全弹性 1.0），按 Coulomb 锥加入切向摩擦冲量，产生 throw 与旋转传递；库边恢复系数 `e_rail=0.78`（原 0.92），加入切向摩擦与侧旋反弹角耦合。
- 击球点仍为中心加八向共 9 档，**偏心幅度未连续化**：`snooker-duel.js` 的 `NOM_BASE=3,600,000` 压住了 pool 指令上界，扩展连续幅度须同步改斯诺克协议，本次采用方案 §4.2 的退化路线未做。
- 电脑对手改为按 ghost ball 瞄准最开阔的袋、按距离调整力度，并使用轻微高/低杆；瞄准线不再画入中袋开口处不存在的库边。
- 分组、犯规、罚杆、8 号判胜与 200 杆上限规则不变。JS 与 Java 双端常量及运算顺序逐项对齐，黄金位置已重刷；Docker 编译测试与 168 组逐帧 parity 验证结果见 `docs/QA.md` 2026-11-10 章节。

### 2026-11-10（二）静止阈值

球静止阈值 `STOP` 由 `.035` 提到 `.2`（JS `pool.js` / Java `PoolRules.java` 同步），单杆回放时长缩短 25–34%，低速拖尾由 2.97s 降到 1.42s。未引入低速线性减速：参数扫描证实那会让球停在袋前、丢失正常落袋，并放大侧旋弧线。球半径、初速 `power×0.48`、阻尼 `0.991^0.25`、2ms 子步、16ms 回放采样、指令编码与全部游戏规则均不变；球尺寸偏大（6.40% vs 真实 4.50%）作为视觉项保留未改。诊断数据、取舍依据与重刷后的验证结果见 `docs/QA.md` 2026-11-10（二）章节。

### 2026-11-20 台球：新增九球玩法（用户确认）

第 10 款游戏「欢乐九球」沿用欢乐台球的球桌、球体、袋口、力量条、击球点、音效、回放、自由球、HUD、装扮、Joy Coins 结算与在线托管，只替换规则。

- 球局：9 颗目标球菱形摆放，1 号在顶点、9 号在中心；状态仍是 53 格、16 球三元组，10–15 号球不摆放且恒为 dead，因此联机快照、回放帧与渲染代码完全兼容。
- 合法目标：`nineballTargets()` 返回台面上号码最小的存活球，每杆白球必须先碰该球；不分组、不清台，落袋任意球且无犯规可继续出杆，借球或组合球打进都算合法。

- 前后端：`dist/table/pool-rules.js` 与 `backend/.../PoolRules.java` 的摆球、目标与结算分支必须逐项一致；八球路径（含黄金轨迹 fixture）逐字未变。新增 `tests/nineball-rules.test.mjs` 与 `NineBallRulesTest.java` 守卫。
