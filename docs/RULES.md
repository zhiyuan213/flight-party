## 当前已实现的基础规则

- 2–4个阵营，每方真人、电脑或关闭；至少一方真人。启用阵营各自竞争，不是2v2。
- 蓝、橙、绿、红，每方两架飞机；当前真人在同一设备轮流操作。
- 每回合掷一次1–6点骰子，选择一架未到终点的飞机；无掷六点奖励回合。
- 不设特定起飞点数，任何点数可以出发。
- 落在敌机所在公共格触发撞击，敌机回基地。
- 达到或超过终点所需步数即可到达，无需刚好点数。
- 操作15秒，超时由本地电脑选择；动画期间不扣时。这不等于联网断线接管已经实现。

## 当前原型参数与旧结束条件

- 公共路线52格，坐标在 `engine.js` 的TRACK，每方起点相距13格。
- 各方5格私人航道，走完后到中心终点；进度0–51为公共格，52–56为私人格，57为完成。
- 基地进度为-1，掷1前进到本方起点0；掷N起飞前进到N-1。
- 四个起点是安全格，不发生撞击。私人航道没有敌方碰撞。
- 同方飞机可同格，不形成阻挡或加成；当前可能视觉重叠，后续需增加叠放展示。
- 同格有多架敌机时一并撞回，每架计1次撞击。
- **旧引擎仍如此运行**：第一名先到两架即记录名次，后续玩家继续，剩最后一方时自动给最后名次并结算。此条将在后续功能开发中被新结束条件替换。
- 关闭阵营仍显示其机场，但没有棋子、不参与回合和投票。

## 后续新规则（本轮只做UI）

- 前两名各自两架飞机都到终点后立即结束；两人局也需双方完成。其余按完成飞机数量、再按进度排定；精确同分比较见V07-CONTRACT建议，后续确定并测试。
- 名次分+2、+1、0、-1。原生电脑参与名次但无账号统计；接管真人的机器人成绩仍属于原身份。
- 登录账号自动记录服务器确认的完整结果，包括负分；账号在正式开局时固定，退出登录不免除本局结算。匿名局中登录默认从后续新局记录；匿名不保存累计积分或局数。没有手动上传/认领流程，不接受客户端自报分数，不追补匿名历史。
- 排行仅积分榜、已完成对局数榜各Top10，移除胜利榜和胜率显示。完成局指正式结算，输赢均只增加1局；取消、等待、重连不算一局。
- 快速匹配直接进入公共空位房，无房自动创建；从房间开始公共匹配起最多30秒，满员提前开始，到期机器人自动补齐。后来加入、离开、重连不刷新时限。
- 创建房间等待邀请朋友，当前真人各自点准备起飞，全员准备后原房加入公共匹配补其他真人；朋友不拆散。邀请等待时不倒计时，一名房主也可准备后开始匹配。
- 线上简化UI默认经典四席，去掉匹配配置表单；这是实现默认，本地2–4阵营选择仍保留。派对与经典不混池，不改基础飞行规则。
- 匿名/登录均可玩；普通每日20局、会员无限；匿名同20局和UTC重置为建议。成功开局扣一次，登录承接同日匿名用量，重连不扣新次数。
- 邮箱密码注册登录无邮箱验证码，保留Google/GitHub入口；不能凭未验证同名邮箱自动合并账号。当前无真认证。
- 断线或主动下线由机器人继续同一席位，重连恢复控制；同局不重复扣次、不重复结算。表情后续向全房间广播，当前仅本地预览。
- 服务端负责骰子、合法动作、回合/匹配时间、名次与统计；验证席位所有权、拒绝客户端修改数据，通过唯一命令与结算事务防重放。修改浏览器不能改变权威对局；当前UI原型尚未具备此安全边界。

## 当前实验性派对模式

- 大厅明确选择Party才启用。经典模式无投票、无道具，不与派对规则混用。
- 完成一轮后逐个未完成阵营投票，每方1票，电脑自动投票。最多4票。
- 二选一：Tailwind全部移动+1（包括基地起飞）；Peaceful skies本轮所有公共格不可撞击。
- 平票随机二选一。事件仅持续下一轮，不叠加；新一轮投票替换。
- 无付费能力，不改变基础投骰概率。未来练习局/派对局是否计入统计与额度仍待确认。

## 当前状态机与后续权威边界

`roll → choose → animating → 下一回合 roll / 下一轮 vote / over`

- 状态机拒绝重复掷骰和重复移动。
- 规则先结算，界面播放同一结果；动画过程中禁用操作。
- 后续联网开发必须由服务器产生规则结果，客户端只渲染，不信任客户端骰子或名次；断线恢复与机器人接管不能重放已经提交的动作。
